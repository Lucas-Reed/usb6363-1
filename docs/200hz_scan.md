# 200 Hz 扫描、逐帧同步和谱线居中

当前实验配置：USB-6363 **单 AI 通道、2 MS/s**，Rigol DG4162 三角波 **200 Hz、5 Vpp、偏置 2.5 V**。
因此一周期是 **5 ms / 10000 点**，半电压起始的三段扫描拐点仍是 **2500、7500**。
输入框为空时按帧长的 25%、75% 计算；也可以手动输入拐点。

## 工控机更新与启动

在原项目目录执行：

```powershell
git pull --ff-only origin master
python -m pip install -r requirements-instruments.txt
powershell -ExecutionPolicy Bypass -File .\manage_services.ps1 -Action Restart
```

统一采集控制台：<http://127.0.0.1:8768>。
设置实际使用的一个 AI 通道（例如 `ai0`）、采样率 `2000000`、每帧 `10000` 点。
启用 PFI0 上升沿启动，重新对齐间隔填 `0`，勾选“每帧对齐 PFI0，记录 PFI1 事件”。
PFI0 使用 `ctr0`，PFI1 使用 `ctr1`，PFI1 边沿为 `FALLING`。
200 Hz 应对应每周期一个 PFI0 上升沿。

双峰页面：<http://127.0.0.1:8766>。显示通道也填写同一 AI 通道。
这个页面的采样率输入不负责更改底层采样率，实际采样配置以 8768 和波形底部信息为准。

## 同步行为

AI task 启动一次后持续采样。两个计数器使用 AI SampleClock 缓存计数，
计数变化对应 AI 的绝对采样位置。输出窗口从每个实际 PFI0 上升沿开始取原始 10000 点，
不再依靠每 100 帧停掉 task 重启来纠正累计偏移。

发布窗口前等待下一次 PFI0 和窗口所需数据齐全。正常 200 Hz 下，
这是等待当前 5 ms 周期结束，再加最多一个读取块的等待，不是增加 100 ms。
启动时计数器第一点只用于建立基线，第一份输出从随后检测到的 PFI0 边沿开始。
计数器与 AI 的硬件路由、同步器延迟仍须实测；0.5 us 是采样网格，不是整个系统的绝对时序精度保证。

窗口保持固定 10000 点，兼容现有双峰和 NPZ 记录。
如果实际周期是 9999 或 10001 点，相邻窗口可能重叠或相隔少量点。
这不会让原始连续缓冲或采样计数漏点；输出窗口没有做插值或拉伸。
状态和波形底部显示 `pfi0_period_samples`，用于判断实际周期是否接近 10000。
连续原始计数按采集块增加，不能再用 `frame_id * 10000` 反推原始采样总数。

PFI1 标记覆盖窗口以及到下一 PFI0 的周期余段；重叠窗口会同时标记。
PFI1 反馈功能已删除，自动居中会跳过被标记的帧。长时间没有 PFI0 时暂停输出同步帧，
持续采样缓冲仍更新，无法无限保留旧触发对应的窗口。

## 手动选峰与跟踪

自动判断 EOM/AOM 级别的功能已删除。分别选择 P1、P2，然后点击下降段上的目标峰。
点击会填入峰顶以及回落至背景的完整左右范围。后续显示帧在上一峰位附近搜索，
更新中心输入框及 P1/P2 竖线；搜索半宽和平滑窗口使用“测峰参数”的设置。
找不到清晰峰时显示错误，不把噪声当成新的峰位。两峰挤到同一峰时同样报错。
这只跟踪手选峰，不识别物理级别。面积统计窗口仍由原有边界设置和“自动跟随面积窗口内最高点”控制。

## DG4162 居中

安装可选依赖后，填写 NI MAX/仪器管理器中的 VISA 地址及实际扫描输出 CH1/CH2。
LAN 常见格式为 `TCPIP0::仪器IP::INSTR`；USB 使用仪器列出的完整 `USB0::...::INSTR`。
Windows USB 连接通常使用现有 NI-VISA。点击连接只查询，不启动信号输出。

程序读取实际幅度、偏置、频率、波形、单位和对称度；三角波应为 `RAMP`、对称度 50%、幅度单位 Vpp。
输出负载设置应与实验接线一致，软件以信号源读回的电压为标尺。
依据为 Rigol 官方 [DG4000 Programming Guide](https://beyondmeasure.rigoltech.com/acton/attachment/1579/f-00b8/1/-/-/-/-/file.zip)，
其中包括 `:SOURn:VOLT:AMPL`、`:SOURn:VOLT:OFFS`、`:SOURn:VOLT:UNIT?`、`:SOURn:FUNC:RAMP:SYMM?`。

先手动减小并固定 Vpp，给偏置调整留出空间。软件不再写幅度，只写偏置。
扫描最低电压必须大于零，页面默认下限 0.01 V、上限 5 V，可按实验调整。
例如 4 Vpp、2.5 V 偏置对应 0.5–4.5 V；5 Vpp、2.5 V 正好触零，没有偏置居中的余量。

选好 P1/P2、解除冻结、连接信号源，然后点击“启动自动居中”。后台默认每秒读取一帧，
按上一位置跟踪两个峰，将中点调整到下降段中心（2500/7500 拐点对应 5000 点）。
默认修正比例 0.3、每次最多调整 0.01 V、中点容差 2 点，均可修改后重新启动。
下降段模型：`偏置修正 = -Vpp × (两峰中点 - 目标中点) / 下降段点数 × 修正比例`。
每次修正还受单步限幅约束，进入容差后保持原偏置。模型按三角波下降段计算，实机首次应观察方向和收敛。

丢峰、帧过期、电压将越界或手动修改仪器参数时停止调整并显示原因，保持最后偏置。
PFI1 影响帧跳过，不参与修正。点击“停止居中”后不恢复旧电压。
关闭网页不会停止后台居中；需要停用时点击停止按钮或停止查看器服务。
仍保留“预览单次居中 / 只写入偏置”，预览冻结显示，不能与自动居中同时使用。
这些操作均不修改频率、波形和输出开关，也不自动改动已有功率锁定窗口。

## 本地已测与实机待测

软件检查命令：

```powershell
python -m unittest discover -s tests
```

覆盖硬件边沿跨读取块的分帧、PFI1 窗口重叠归属、原始缓冲计数、
手选峰漂移跟踪、固定 Vpp 的偏置居中、失峰停止，以及模拟信号源闭环收敛。
这些检查不能代替 USB-6363 和 DG4162 实机测试。

现有 `buffered_pfi_report.json` 是三通道 100 kS/s 的结果。
**单 AI 2 MS/s 加两路同步计数器的吞吐量仍需验证**，不会自动降低 AI 采样率。
先停止占用设备的服务，在有 PFI0/PFI1 信号时执行已有诊断：

```powershell
powershell -ExecutionPolicy Bypass -File .\manage_services.ps1 -Action Stop
python verify_buffered_pfi.py --device Dev2 --channels ai0 --rate 2000000 --seconds 60 --block-samples 10000 --pfi0-counter ctr0 --pfi1-counter ctr1 --output buffered_pfi_2msps.json
```

将 `ai0` 改为实际通道。诊断结束后重新启动服务，按上述参数启动统一流，
检查周期约 10000 点、波形不再持续横向漂移、采样计数持续增长，且无 DAQmx 错误。
将 `buffered_pfi_2msps.json`、统一流状态和一份实际光谱样本发回即可继续判断。
无光时可验证触发与吞吐；振铃下的峰跟踪和偏置居中效果须有光验证。
